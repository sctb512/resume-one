Initial modification by Resume One contributors: fontTools 4.68.0 instantiated the
upright variable font at wght=400, 600, 700 and 800. No theme code was executed.
No glyph subsetting, outline redesign or font installation was performed.
The variable source is retained only in the ignored per-theme QA directory;
the distributable package contains only the four static TTF faces below.
Variation tables and their obsolete STAT/instance-name records were removed.
Copyright, designer and license records remain intact. These initial static
faces shared the family Resume One Californian Nunito; their SHA-256 values
are retained below as the before-renaming lineage.

CW09 follow-up modification: fontTools 4.68.0 mechanically renamed only the
four already approved static faces, without re-instantiating the variable
source. Each face now has its own family Resume One Californian Nunito W400,
W600, W700 or W800. Family names 1/16/21 agree within each face; subfamily
names 2/17/22, full name 4, unique identifier 3 and PostScript name 6 also
identify the same face consistently. Other name records remain byte-exact.
This isolates each face in the exporter's family-keyed regular/bold slots:
the previous shared family put 600/700/800 into one embedBold slot. Unique
per-face families remove that candidate-level key collision and also retain
the package-specific prefix. Actual DOCX embedding and Word rendering remain
the main agent's separate checks; no new DOCX/PDF export is claimed here.

Follow-up identity audit on 2026-10-30 checked nameID 18 (compatible full
name), 21/22 (WWS family/subfamily) and 25 (variation PostScript prefix) in
all platform/encoding/language records of all four final static faces.
Neither 18 nor 25 exists in these faces; no optional record was invented.
Existing 21/22 records already match each independent W400/W600/W700/W800
family and its true subfamily. No old selection identity remains in those
records. The regeneration helper now aliases existing 18 to the new full
name and existing 25 to the new family PostScript prefix when present.
Regeneration into a separate QA output directory reproduced the current
fonts byte-for-byte, including every table; all four Current SHA-256 values
below are unchanged. Original copyright/license records were not edited.

Before/after comparison checks every original SFNT table. Only name and
head differ; the only changed head field is checkSumAdjustment. In particular
glyf/loca, hmtx/hhea, OS/2, cmap, maxp, post, prep, gasp, GDEF, GPOS and GSUB
are byte-identical to the initial static faces. No outlines, metrics, glyph
ordering, shaping tables, hinting or head timestamps were changed. Every
table checksum and the complete SFNT checksum 0xB1B0AFBA are verified.
All four actual OS/2 weights match the manifest, fsType=0 permits embedding,
and every face contains basic Latin m. The original source has no CJK glyphs;
the application supplies its explicit bundled Noto fallback for CJK.
