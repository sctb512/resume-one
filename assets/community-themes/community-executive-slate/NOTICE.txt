PRESERVED STRUCTURE AND MEASURABLE VALUES
The identity, contact information, skills, education and languages occupy a
dark LEFT sidebar. The summary starts the main column; work, projects,
volunteering, awards, certificates, publications, interests and references
are also in main. Contacts stack. Work/volunteer dates align to the right.
The sidebar uses the exact upstream PRINT solid slate #475569; the screen
gradient is not reproduced. Main paper is #FFFFFF, ink #334155, headings
#475569 and date metadata #6B7280, all from Resume.jsx. Border #94A3B8 is
the upstream short rule accent, reused as the available single border token.
The application canvas #F1F5F9 is an adaptation choice, not an upstream value.
Main summary/body 15px maps to 11.25pt, main section titles 24px to 18pt,
main work/project titles 20px to 15pt, and dates 14px to 10.5pt. Body line
height 1.8 and name line height 1.2 match explicit source values. Name size
33.75pt before sidebar scale 0.8 yields the source's 36px / 27pt name.
Label now uses the actual 500 face at 14.0625pt before sidebar scale 0.8,
yielding the original 15px / 11.25pt. Its +0.5px tracking is 1/30 em.
Summary uses the 400 face at the source's 15px / 11.25pt and 1.8 line height.
Side dates use their own 500 face at 14px / 10.5pt, independently of metadata.
Name tracking is -0.5px / 36px = -1/72 em, yielding -0.375pt after scaling.
Main section tracking is +1.5px / 24px = 1/16 em. Label and section headings
are uppercase presentation only; no resume JSON or module text is rewritten.
Declared asset weights are the actual static weights. The application
continues to use its explicit CJK fallback for unavailable glyphs. Native
Word's style matching / synthetic styling has not been accepted by this task.

BLOCKING DIFFERENCES AND ORIGINAL EVIDENCE
1. Per-region geometry / full-bleed sidebar:
   Layout declares grid-template-columns: 320px 1fr and max-width: 1100px;
   Sidebar padding is 60px 40px; MainContent padding is 60px 50px, changing
   to 40px in print. The v2 renderer supplies percentage columns, uniform
   page margins and fixed 6pt sidebar insets, not independent region padding
   or a page-edge sidebar. This candidate uses 32%, 9mm gap, top/bottom
   15.875mm and left/right 10.5833mm. These are not geometrically equivalent.
2. Independent regional and semantic typography:
   SidebarSectionTitle is 16px while StyledSectionTitle is 24px; sidebar
   text is 14px, sidebar contact/degree 13px, sidebar education title 14px.
   Source Name is 36px, Position 20px, Institution 18px, Company 17px/600,
   Label 15px/500, SidebarSkill strong 13px/600. V2 now has eight shared roles
   plus one sidebar scale, so these independent sizes/weights/families
   cannot all be matched. Scale 0.8 produces sidebar body 9pt, heading
   14.4pt, item title 12pt and metadata 8.4pt; the corresponding source
   sizes are 10.5pt, 12pt, 10.5pt and 9.75pt. The identity name is 27pt.
   V2 also uses one item title size across work, education, awards, skills
   and languages; sidebar skill names are therefore serif, unlike source.
   V2 company, position, institution and degree mappings cannot be chosen
   independently by this manifest. No source data is rewritten to fake them.
   Label, summary and side-date font/size are now independent and no longer
   blocked by the old body/meta role coupling. Contact/degree/category roles
   and per-region section-heading typography remain coupled.
3. Remaining regional tracking mismatch:
   Label and both section-title styles now use supported uppercase, and
   the explicit name, label and main-heading tracking matches source values.
   SidebarSectionTitle requires +1px at 16px (1/16 em); this candidate's
   shared 18pt heading scaled by 0.8 is 14.4pt / 19.2px with 0.9pt / 1.2px
   tracking. There is still no separate sidebar heading size/tracking role,
   so the source's 12pt heading / 0.75pt tracking cannot both be matched.
   No unsupported italic style or arbitrary CSS is declared.
4. Rules, colors and background treatment:
   StyledSectionTitle has a 3px #475569 bottom rule plus a 60px-wide
   #94a3b8 ::after segment. SidebarSectionTitle uses 2px white at 30%
   opacity, and Label uses 2px white at 20% opacity. V2 exposes only uniform
   0.6pt/1.2pt section rules and a global header separator; it cannot draw
   the short second-color segment or separate label/title rule opacities.
   The screen sidebar is a #475569 -> #334155 vertical gradient; v2 is solid.
   Main Position/Institution use #1f2937, Company #2f4f4f and paragraphs
   #4b5563; source sidebar text uses white/#e2e8f0/#cbd5e1. Exact name,
   label, main summary and standalone-date foreground declarations are now
   independent and pinned as listed above. Body, meta, sectionTitle and
   itemTitle still lack separate regional/field colors, so their semantic
   and automatic readable sidebar colors are retained. Exact matching of
   those source colors, rule alpha and the screen gradient remains blocked.
5. Independent spacing and line heights:
   Header bottom margin is 50px; Label bottom margin and padding are 30px;
   main titles have 50px top / 30px bottom / 12px bottom padding; sidebar
   titles have 40px top / 20px bottom / 10px bottom padding. WorkItem uses
   40px bottom spacing; EducationItem 28px; sidebar items 20px. WorkHeader
   has a 20px gap and 12px bottom margin; summary bottom margin is 30px.
   Highlights have 24px indent, 6px item padding and 10px vertical margins;
   WorkSummary uses 14px paragraph margins. V2 exposes one sectionGapMm
   (here 10.5833mm / 40px), fixed stack gaps and shared line heights. It
   cannot express these per-region/per-module/per-element values. The
   candidate's title leading (1.3) and date leading (1.5) are adaptation
   choices, not separately declared source values.
   Label's line height also remains inherited from this candidate's body
   role (1.8); the source label itself has no explicit line-height value.
6. Heading text, module order and field presentation:
   Source fixes sidebar order skills -> education -> languages and main
   order work -> projects -> volunteer -> awards -> certificates ->
   publications -> interests -> references. V2 preserves input JSON order
   within each region and provides localized standard headings, so it cannot
   force source labels such as Professional Experience / Notable Projects /
   Awards & Recognition or reorder existing data. Source uses comma-joined
   skills and "studyType in area" education, while v2 uses shared semantics.
   Source omits some standard fields (for example education courses/score,
   skills level and project dates/URL); v2 preserves and displays supported
   nonempty data. No data is dropped to resemble the source.
7. Screen behavior / print pagination:
   Source collapses the two columns below 900px, stacks work headers below
   640px, adds a layout shadow and hover link behavior, and has no v2 PDF
   page-number semantics. V2 uses fixed A4/Letter pages, independent column
   pagination, protected headings/items and its standard page footer.
   Responsive breakpoints, shadow, hover behavior and exact upstream print
   pagination are not represented. SkillsGrid / SkillCategory declarations
   are unused by the original Resume component and are not recreated.
8. Latin wrapping observed in the current supplied CLI:
   The synthetic name "Alex Morgan" wraps as "Alex Morga" / "n" at the
   candidate's sidebar width. "Business Transformation" also splits inside
   its final word. The source's normal browser text wrapping would prefer
   word boundaries. This is a rendering blocker, not accepted typography.
   Evidence: target/community-executive-qa/en-independent-families-1.png.
   The current supplied CLI binary SHA-256 is
   63fd5d59daf98fe93ad041cc4904107654564acf5ce8d00a747823e4f23156ce;
   later shared-code changes require separate integration and rerendering.
